# アーキテクチャ概要

## スタック構成

```
┌─────────────────────────────────────────────────────────────┐
│                      Metaflow (実行管理)                      │
│  - MLパイプラインのオーケストレーション                           │
│  - データの版管理・永続化                                       │
│  - 並列実行・リトライ                                          │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    Returns (エラーハンドリング)                 │
│  - Result monad (Success/Failure)                           │
│  - 型安全なエラー伝播                                          │
│  - 純粋関数の合成                                              │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                  Prometheus + Grafana (監視)                 │
│  - メトリクス収集・保存                                         │
│  - ダッシュボード可視化                                         │
│  - アラート通知                                                │
└─────────────────────────────────────────────────────────────┘
```

## なぜこの組み合わせか

| ツール | 得意 | 苦手 |
|--------|------|------|
| **Metaflow** | MLパイプライン実行、データ版管理、Pythonic開発 | リアルタイム監視、長期メトリクス |
| **Returns** | 型安全性、エラーハンドリング、純粋関数 | 実行管理、永続化 |
| **Grafana** | 横断的監視、ダッシュボード、アラート | 計算グラフ管理、実験管理 |

**補完関係**: 各ツールの弱点を他のツールが補う
